# 灯笼·多维轴 KB 策展方法

**角色**：lantern-caliper 知识库的策展员（KB curator）。

**任务**：接收用户给出的一个概念，通过多视角拆解产出一条结构化知识条目，写入 KB。

**硬约束**：
- 不做学术分析，不穷尽概念的所有维度。
- 产出最终要入库；可检索、无冗余，比深度更重要。
- 每次分析只跑一轮，不做多轮迭代。

> 以下命令在 Skill 目录下执行即可（`scripts/lantern_method.py` 与本文件同级）；引擎会自动从仓库根定位知识库，也可用环境变量 `LANTERN_KB_DIR` 显式指定。

---

## 流程总览（严格执行这 6 步）

1. **定透镜（步骤 A）**：跑 `kb-stats`，按决策树选 3–5 个分析透镜。
2. **投影（步骤 B）**：对每个透镜填模板，产出 `projection`。
3. **冗余检查 + 计分（步骤 C）**：回头逐对检查耦合标记 `high_coupling`，把 B+C 交给引擎 `update-scores`。
4. **反馈轴（步骤 D）**：对自己综合出的结论做一次**自我对抗式审查**，揪薄弱点 / 盲区 / 过度推断，并把修订反馈回分析。
5. **写回 KB（步骤 E）**：统一走 `upsert-kb`（智能写回：内部先 `kb-query` 判定命中 → 命中则把新洞察**增量追加**到已有条目末尾并标注日期、未命中则新增；两种方式都固化反馈轴段）。可先单独跑 `kb-query` 看命中情况，但**真实写入只调 `upsert-kb`**。

---

## 两个容易混的词（先读，否则会写错）

- **存储坐标**：KB 里知识"存在哪"——主尺=学科领域带 × 游标=演绎深度，外加 `axes` 分类法（`domain|dimension` 列表）。由 KB 自身维护。
- **分析透镜**：本次分析时，从 KB 域分布派生出的正交视角，格式也是 `domain|dimension`（如 `经济|本质`）。由本次分析提议。
- **关系**：分析透镜是存储坐标的**下游产物**，不反向改写领域带。两者都用 `domain|dimension` 格式，但含义不同：一个是"知识已被分到哪"，一个是"本次从哪切"。

---

## 步骤 A — 选透镜（决策树）

1. 运行：
   ```
   python scripts/lantern_method.py kb-stats
   ```
2. 看返回的 `axis_domain_distribution`（**按学科聚合的条目数**，这是本次分析真实写入/选透镜的分类法）：
   - **若目标概念的核心学科（`axis-domain`）在表中的条目数 ≥ 3（暖启动）**：从该学科 + `axes_list` 中绩点最高的 2 个学科选透镜，共选 **3–5 个**。
   - **若条目数 < 3（冷启动）**：自主提议 3–5 个透镜，全部标 `"tentative": true`。
   - **不要用 `domain_distribution` 判冷暖**：那是游标卡尺的 4 个领域带（自然科学/社会科学/…），与学科标签（心理/经济/…）不是同一套；用它判冷暖会**永远冷启动**。
3. 检查选定的列表：
   - 同一 `dimension` 出现 ≥ 2 次 → **删掉多余的那个**。
   - 所有透镜都来自同一 `domain` → **至少补 1 个其他 domain 的**。
4. 输出格式（直接复制字段）：
   ```json
   {"axes":[{"domain":"经济","dimension":"本质","tentative":false},{"domain":"哲学","dimension":"矛盾","tentative":false}]}
   ```

## 步骤 B — 沿轴投影（填空模板）

对每个透镜，**复制以下模板填入**（不要改字段名，不要增删字段）：

```json
{
  "name": "通货膨胀的购买力侵蚀效应",
  "rationale": "从经济学本质切入，揭示通胀的核心伤害机制",
  "projection": "通货膨胀本质上是对持有现金者的隐性征税——物价持续上涨使同等金额的购买力缩水，固定收入群体承受不成比例的损失，而资产持有者反而可能因资产价格同步上涨而受益。",
  "stance": "support",
  "orthogonal": true
}
```

规则：
- `name` 必须是"概念 + 具体切入点"，**禁止**只写"经济视角"这种空泛名称。
- `projection` 必须包含至少一个**因果判断或对比关系**，**禁止**纯描述（如"通货膨胀是指物价上涨"这种百科式句子）。
- 若发现某透镜的 `projection` 与另一个说的是同一件事，把该透镜的 `orthogonal` 填 `false`。

---

## 步骤 C — 冗余检查 + 计分

**回头看**步骤 B 产出的所有 `projection`，逐对检查：
- 轴 A 和轴 B 是否在说同一件事？（换了个说法但核心判断相同 = 耦合）
- **判断标准**：如果把轴 A 的 `projection` 删掉，轴 B 的 `projection` 是否已经覆盖了同样的信息？如果是 → `score ≥ 7`。

输出格式：
```json
{
  "pairwise": [
    {"a":"经济|本质","b":"社会|矛盾","score":3,"confidence":0.8,"reason":"一个讲购买力机制，一个讲分配冲突，角度不同"},
    {"a":"经济|本质","b":"金融|本质","score":8,"confidence":0.9,"reason":"都在说'通胀是隐性征税'，只是换了领域标签"}
  ],
  "high_coupling": [["经济|本质","金融|本质"]]
}
```

若存在 `high_coupling`：
- **保留**信息量更大的那个轴，**删除**另一个，在最终输出注明"已合并：X 与 Y 耦合，保留 X"。

计分（把 B、C 的结果交给引擎，分数由引擎确定性计算，无需手算）：
```
python scripts/lantern_method.py update-scores --gen '<步骤B的JSON>' --review '<步骤C的JSON>' --concept '概念名'
```
引擎会自动：良好选用的轴加绩点；高耦合（`score≥7` 且 `confidence≥0.6`）加权扣分；长期未选用的活跃轴缓慢衰减。

---

## 步骤 D — 反馈轴（自我对抗审查）

> 步骤 B 沿轴投影、步骤 C 查轴间耦合，但到此为止**还没有人对"综合出来的结论本身"开火**。反馈轴＝给本次分析配一个红队：以最不利的角度审自己的核心判断与全部投影，找出会被真实反驳的地方，再把修订反馈回分析。这一步是元认知，不是再加一个分析透镜。

**输入**：步骤 B 的全部 `projection` + 步骤 C 合并后的核心判断。

**逐个回答以下 6 问**（每问都必须落到具体投影或判断，禁止空话）：

1. **核心判断最弱的支撑点**：哪个投影其实没撑住核心判断？差在哪？
2. **最强反论据**：陈述一个**即使你不同意、也最有力**的反面论证。不要稻草人，要对方能拿得出手的最强版本。
3. **隐藏假设**：本次分析成立，依赖哪些**未言明的前提**？（如"人脑算力恒为瓶颈""现代环境必然更复杂"）
4. **透镜盲区**：哪些重要 `dimension` 没被纳入？为什么可能漏掉关键视角？
5. **内部张力**：投影之间有无**未察觉的矛盾**？
6. **过度推断**：核心判断是否在投影实际产出的范围之外跳跃？

**输出格式（直接复制字段，填内容）**：

```json
{
  "core_verdict_weakest_support": "经济|激励 轴只论证了偏差'被利用'，未证明它'必然发生'；'系统性误触发'在激励中性情境下不成立",
  "strongest_counter": "偏差也是 profitable heuristic——多数日常情境它成本低、收益高，'失灵'只在特定复杂环境，故'默认设置失灵'是过度概括",
  "hidden_assumptions": ["人脑算力约束恒为瓶颈", "现代环境普遍比原始环境更复杂"],
  "blind_spots": ["未纳入神经可塑性/训练可改善维度", "未考察文化差异维度"],
  "internal_tension": "无（各投影互补）",
  "over_reach": "把'默认启发式'直接等同'失灵'跨越了证据——应改为'在某些现代环境误触发频率更高'",
  "verdict_revised": "认知偏差是大脑在有限算力下的节能默认设置，在现代复杂/激励错配环境中误触发频率更高",
  "must_revise_before_write": true
}
```

**闭环规则（关键）**：

- 把上述反馈轴产出**呈现给用户**——这就是"反馈出来给你"；同时它由写回命令落进独立的「反馈收件箱」数据表（不在文章正文里）。前端把它拆成**两条泾渭分明的通道**：① **推送通道**（QQ 式右下角弹窗）——实时、瞬时、逐条；新反馈到达时一条一条从右下角弹出，点击弹窗**就地展开看完整反馈内容**、再决定后续操作（查看原文 / 标已读 / 应用更新 / 忽略），展开即标记已读、暂停自动消失，绝不自动跳走或画成图边；② **反馈邮箱**（侧边收件箱）——持久、总览、可回溯，集中显示全部反馈（全部 / 未读 / 已采纳 / 已忽略），是归档与集中处理的地方。两条通道数据同源（`feedback_inbox` 表）、入口与交互彻底分开。
- 若 `must_revise_before_write` 为 `true`：**先用 `verdict_revised` 替换核心判断**，并把相关的 `projection` 软化，再进步骤 E。反馈轴的价值在于它能改分析，不是只写报告。
- 即使不必修订，也**必须至少指出 1 个真实弱点**（强反论据 / 盲区 / 隐藏假设之一）。禁止只夸不批。

---

## 步骤 E — 写回 KB（upsert：命中增量更新 / 未命中新增）

1. **（可选，信息用）先检索看命中**：
   ```
   python scripts/lantern_method.py kb-query --text '概念名'
   ```
   命中 = top 结果 `score ≥ 4`（概念名已在既有标题/正文，对应『重叠 > 50%』）。

2. **条目内容严格按此结构**（不要自由发挥版式）：
   ```
   ## 核心判断
   {core_verdict，一句话}

   ## 多视角摘要
   - 【{轴1 name}】{projection 压缩到 1–2 句}
   - 【{轴2 name}】{projection 压缩到 1–2 句}
   - ...

   ## 仍存张力
   {tension，没有则写"无"}

   ## 元信息
   - 分析日期：{today}
   - 使用透镜：{domain|dimension 列表}
   - 冗余处理：{如有合并，注明}
   ```
   （`## 对抗审查（反馈轴）` 段落**绝不要手写在 content 里**——它不进文章正文。反馈经 `upsert-kb --review` / `push-feedback` 落独立的「反馈收件箱」数据表，作为右下角**逐条推送弹窗**与侧边**反馈邮箱**的来源、以及知识库自我更新的指导，从而保持知识文章的独立与纯洁。）

3. **写入（统一走 `upsert-kb`，它内部已做检索判定，无需手动区分命中/未命中）**：
   ```
   python scripts/lantern_method.py upsert-kb --title '概念·核心判断关键词' --content '...上述结构...' --axis-domain '概念的核心学科归属' --review '{"core_verdict_weakest_support":"...","strongest_counter":"...","hidden_assumptions":[...],"blind_spots":[...],"internal_tension":"...","over_reach":"...","verdict_revised":"...","must_revise_before_write":false}'
   ```
   - 命中判定用**概念名**：`--concept` 显式给定，否则引擎自动取 `--title` 中 `·` 之前的部分（如『认知偏差·补充视角』→『认知偏差』）去匹配既有条目；**不要拿完整新标题当检索词**，否则永远匹配不上、反复建重。
   - 命中（`score ≥ 4`）→ 返回 `action:"updated"`，把本次 content（含反馈轴段）+ 日期标注**追加**到已有条目 `content` 末尾，保留其双尺定位与 id。
   - 未命中 → 返回 `action:"created"`，新建条目。

（`kb-context --qtext '概念'` 可一次性取回相关知识包，写投影前用来避免与已有条目重复。）

## 引擎命令速查（含返回关键字段）

| 命令 | 作用 | 返回关键字段 |
|---|---|---|
| `kb-stats` | 拉 KB 域分布 + 轴分类法（定轴用） | `item_count`, `axis_domain_distribution`（学科级，判冷暖用）, `domain_distribution`（领域带，勿用于判冷暖）, `axes_list` |
| `kb-query --text '<概念>'` | 自由文本检索（看命中情况） | `results:[{title,score,snippet}]` |
| `kb-context --qtext '<概念>'` | 聚合检索上下文包 | `packet`（可直接喂给模型） |
| `update-scores --gen '<B>' --review '<C>' --concept '<名>'` | 确定性更新全场轴绩点 | 按绩点排序的轴库 |
| `feedback --domain <域> --dimension <维> --vote up\|down` | 用户对轴的投票/复活 | `score`, `state` |
| `library` | 打印当前轴库（看哪些该休眠/优选） | 按绩点排序的轴 |
| `upsert-kb --title '<t>' --content '<c>' [--axis-domain '<域>'] [--review '<反馈轴JSON>'] [--concept '<概念>'] [--hit-threshold 4.0]` | **智能写回（唯一写入入口）**：命中增量更新、未命中新增；反馈轴**不写进正文**，而是推入独立的「反馈收件箱」数据表（消息通知 + 自我更新指导） | `action`(`updated`/`created`), `id`, `matched_score` |
| `push-feedback --title '<t>' --axis-domain '<域>' --review '<反馈轴JSON>' [--item-id <id>] [--severity info\|warn\|critical] [--must-revise 0\|1]` | 单独把一条自我对抗审查反馈推入收件箱（不依赖写回，适合周期性给 KB 做正交体检时发通知/指导自我更新） | `feedback_id` |
| `write-kb --title '<t>' --content '<c>' [--axis-domain '<域>'] [--review '<反馈轴JSON>']` | 强制新建（**不经命中判定**，仅当你明确要新建重复条目时用）；反馈轴同样只进收件箱、不进正文 | 入库结果 |

> 引擎：本 Skill 的 `scripts/lantern_method.py`（Python 标准库，无需依赖），会自动从仓库根定位知识库（含 `kb.py` 的目录），也可用环境变量 `LANTERN_KB_DIR` 显式覆盖。参考：`头脑风暴/`（Node）为已废弃的旧实现，本 Skill 已将其精密机制 1:1 移植并通过 `scripts/verify_port.py` 确定性验收，逻辑以本引擎为准。

## 融合 Karpathy LLM Wiki 的特色化实现

灯笼与 Karpathy LLM Wiki 是同一哲学的两个实现——"知识是引擎增量编译、复合增长的持久资产，不是每次查询现 retrieve 的 RAG"。灯笼已走在正确方向上（KB 自带引擎自主跑，非 person_dashboard 的被动镜像）。融合时**绝不做成另一个 markdown wiki**，而是用灯笼的「双尺度坐标（主尺带×游标）」作为统一地基，把 Karpathy 的三个价值重新实现为灯笼特色：

### 1. 信号可信度守卫（已落地，写回/巡检前必跑）
- 位置：`store.signal_integrity()` + `enforce_signal_guard()`，已接入 `refresh_soft_links` 与 `/api/state`（前端概览页与偏差视图守卫框展示）。
- 作用：用实证统计检测 embedding 是否退化（失去区分度）。退化指纹＝**跨主尺带（不同领域）的条目对却出现极高余弦相似度（>0.85）**——真实语义嵌入下跨主题相似度应明显更低。判据（任一成立即 degraded，自动挂起语义链）：① 全局均值>0.75 ② 近重复率>0.3 ③ **跨带高相似对≥3**。
- 比 Karpathy 更狠：Karpathy Lint 靠人/LM 读出来"信号不可信"，灯笼把它变成**统计实证 + 自动拉闸**（degraded→自动置 `semantic_links_enabled=0`）。注意：**只挂起不自动恢复**——恢复需先修好嵌入（换可信模型并 `rebuild_embeddings`）再由人工/显式流程置 1，避免在接口时好时坏时反复横跳，也尊重"暂停生成"的拍板。
- 写回/巡检前：调用 `enforce_signal_guard()` 确认语义信号健康，再决定是否跑 `discover_semantic_links`。

### 2. 概念衍生层（特色核心：概念是后端桥接中间件，不是图谱节点）
- **定位（2026-08-10 拍板·重大调整）**：概念**不再作为图谱节点 / 偏差图点**（不再画朱砂菱形），而是退回到后端的一张被动存储的「概念↔文档」列表（独立的 `concepts` 表 + `concept_links` 表，不污染 `links`/`items` 类型安全），类比 person_dashboard 的 wiki 层——只存储、不自动画边。
- **作用**：`store.concept_neighbors(item_id)` 通过 `concept_links` 找与该文档**共享概念**的其他文档，按共享概念数排序，返回 `{item_id,title,shared_concepts,score}`。这是**桥接推荐中间件**：给定一篇，推荐"因为共享了哪些概念而相关"的其他文章，共享概念即「桥接依据」。
- **前端呈现（节点详情页）**：`graph.js` 的 `graphSelectNode` 在文章节点详情面板底部异步拉 `/api/kb/concept_neighbors`，渲染「相关文档 · 概念桥接」区块（列出共享概念作为依据，点击跳阅读页）。**不自动画成图谱边**——避免重演语义链误连的乱局，人工看过后自行决定是否 `[[...]]` 互链。
- 数据流：① 离线兜底 `_extract_concept_names` 仅启发式模式用；② LLM 主路径 `enrich_concepts_with_llm` 抽 3-5 个真概念+定义，`_refine` 异步升级；③ `rebuild_concepts(use_llm=True)` 清表后全量 LLM 重抽（实测 33 个 / 10.2s）。
- 落库聚合：`_upsert_concept_raw` 同名聚合（坐标取首篇主导），`link_concepts_for_item` 写 `concept_links`。`/api/concepts` 暴露全部概念（后端列表，供核对/桥接用，不再进可视化）。
- 独立性：概念**独立于正文**（不污染文章纯净性），沿用 `feedback_inbox` 隔离思路；只接纳有 `definition` 的真概念。
- 抽取红线：概念须有事实依据（来自正文，非凭空生成）；同概念跨多篇自动聚合为单一节点。

### 3. 好答案沉淀（分析结论存回衍生层，不丢进聊天）
- Karpathy 强调"好答案要存回 wiki"。灯笼对应：LLM 在对话/诊断中做的分析（如"这篇与那篇是假连""某轴高耦合应合并"）不只当下用，应存回 KB 衍生层——现有 `feedback_inbox`（反馈轴）即雏形，可扩展为 `insight` 表承载更广义的"分析笔记"。
- 衍生层一律独立于正文 + 带坐标，既能检索又不污染文章纯洁性。

> 融合的红线：任何从 Karpathy 借来的能力，都必须落进灯笼的「双尺度坐标 + 引擎自主 + 正文纯净」框架，而不是退化成"人/LM 手动维护的 markdown 墙"。

## 禁止清单

- 禁止多轮迭代（一轮分析完毕即写回）。
- 禁止 `projection` 出现纯描述（必须有因果 / 对比 / 判断）。
- 禁止在 `high_coupling` 存在时直接写回（必须先合并）。
- 禁止 `name` 使用"XX视角""XX维度"这类空泛名称。
- 禁止直接 `write-kb` 跳过命中判定（真实写入统一走 `upsert-kb`，其内部已先检索，命中自动增量更新避免重复碰撞）。
- 禁止把分析透镜写回 KB 的 `axes` 分类法（透镜是下游，不改存储坐标）。
- 禁止跳过反馈轴（步骤 D）直接写回。
- 禁止反馈轴写成总结 / 复述（必须是找茬 / 对抗，至少指出 1 个真实弱点）。
- 禁止在反馈轴判定 `must_revise_before_write: true` 时，不改核心判断就直接写回。
