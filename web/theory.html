灯笼 · 多维轴知识库

从游标卡尺到阴阳闭环 —— 理论修订稿 v2
本文是把一段连续对谈收敛成形的修订稿。核心结论：文件夹/标签是一维路径，不够； 真正的出路不是"发明多维"，而是把多维检索下沉为默认且零成本的用户层—— 用游标卡尺式的连续刻度替代离散分类，用阴阳双模型闭环替代单模型判读。 本文先修正理论，再给出可跑的原型。

一、缘起：一维路径的尽头

无论文件树、笔记标签还是 wiki 分类，本质都是一维路径的层层深入：一个知识只能被放进一条链路的某一格。 数据少时尚可，进入大数据与 AI 时代后，AI 的智能与决策依赖快速、可并行的检索与存储，一维结构明显失速。

但必须校准一句："多维检索该诞生了"这句话对基础设施层已经成立——关系库按列组合查、图库把关系当维度、向量库是语义维度、搜索引擎倒排索引本就是多词多维。 真正的缺口在两层：① 用户默认心智仍是文件夹；② 维度的产生方式是反的——过去让人手打十个标签，而这恰恰失败了，因为人不会持续维护。

所以机会不在算法，而在体验与自动化的最后一跃：数据存一份，AI 自动从内容抽出多个轴，索引随数据同步更新；检索时沿任意轴或组合切片。

二、核心隐喻：游标卡尺，而非标签

普通标签是"把这条知识塞进 A 类或 B 类"——离散、强制、非此即彼。卡尺的破局点在读偏移：

  • 连续度量 vs 离散分类：一条知识可同时"在 40.x 像主题 A、在 82.y 像实体 B"——连续、可同时、肉眼可见。
  • 卡尺的真正威力 = 读两尺之间的偏移：主尺给粗定位，游标给细定位，精度来自两尺之差，而非任何一把尺单独给的数。所以两个测量源的价值在于它们的分歧是高分辨率信号。
  • 可视化不是装饰：刻度点在横梁上的位置，比一行"相似度 0.37"直观得多。可视化是让连续相似度"可读"的介质。
图 1 · 游标卡尺思维：相似度是连续刻度，精度来自两尺偏移

三、双尺映射的修正（关键修订）

最初我把双尺设为"主尺=语义(阴)、游标=视觉(阳)"。经讨论，这仍偏向"换标签列"。 修订为更锋利的映射：

主尺 = 学科领域划分（粗粒度分类，偏 阳·感知归类）
游标 = 抽象逻辑演绎深度（连续谱 0 描述叙事 → 100 形式证明，偏 阴·深层推理）

为何这样分：逻辑跨域通用——三段论不在乎你讲物理还是经济，所以游标是"近普适刻度"； 领域是人造分类，所以主尺是"相对刻度"。把"相似"重定义为"逻辑形态相同，不论主题"。

顺带一个观察：这把之前的阴/阳翻转了——说明阴阳不是固定属性，而是随你想测量什么而重指派的。框架是活的。

四、碰撞出了什么（领域 × 逻辑演绎）

图 2 · 红点 = 逻辑演绎深度远超所在领域典型值，即跨域同构碰撞点

五、阴阳闭环：互缠互生

图 3 · 阴生阳、阳生阴，差异报告即游标偏移＝反馈信号

阴生阳：推理大模型产出结构 → 视觉大模型渲染/校验；阳生阴：视觉回报"你写的结构说 A，图里实际聚成 B"→ 推理修订。 这个差异报告就是卡尺的偏移读数。闭环必须锚定真实存证，否则两模型互相喂会发散成螺旋而非环。

六、与知识图谱的异同与互补

维度知识图谱游标卡尺轴
结构本质离散符号：关系要么有（边）要么无连续刻度：可同时 0.37 像 A、0.82 像 B
关系来源本体/关系抽取 + 人工校对（ontology 瓶颈）尺子自动投影，不手建 schema
关系意义边自带语义，可解释关联隐式，需读偏移/日志才知"为什么"
跨模态几乎纯文本符号天生带阳（视觉/形态）刻度
维护成本实体消歧、schema 膨胀随规模陡增加条目只是投影；但失去实体身份

互补而非对手：图谱作显式骨架（确定关系），卡尺作模糊发现面（相似度+跨模态）； 而卡尺的未对齐信号反向喂给图谱——当阴阳两尺持续对不齐某条 A↔B，系统提议"是否补一条关系边？"。 图谱管确定、卡尺管发现、闭环管生长。

七、必须修正的三个理论风险
  1. 两尺必须独立，否则偏移是噪声。这是卡尺威力的命根。若"领域"与"逻辑演绎"都来自同一个推理模型，二者高度相关，偏移坍缩成噪声。 工程上须让主尺来自分类/embedding 一路，游标来自形式化/结构化分析或视觉另一路。
  2. "逻辑是绝对游标"是哲学立场，非事实。经典逻辑、直觉主义、各学科推理规范并不统一。游标应标为"本推理模型所操作化的逻辑"，仍是模型依赖。
  3. 领域本身是谱系、杂交的。强制塞进单一主尺会丢掉落杂交项（如"计算神经科学"），此时反而是游标（逻辑形态）比主尺更可靠。

八、从隐喻到规范：schema v1.0.0

一个比喻要成为工程，必须先变成可校验的规范。schema.json 把两尺固化为可计算的定义：

  • 共享横梁：单位 ld（lantern-degree），值域 0–100，左端具体/描述，右端抽象/形式化。任何尺子的读数都必须归一到此标度，否则偏移不可比。
  • 主尺 scale.main.domain：四条领域带（人文 / 社会科学 / 自然科学 / 形式科学），provider 信号族 topical-lexicon，只读主题词。
  • 游标 scale.vernier.deduction：0–100 连续谱，锚点为 描述 → 归纳 → 条件 → 论证 → 形式证明；provider 信号族 argumentative-syntax，只读论证句法，不读任何领域词。
  • 偏移：offset = 游标实测 − 所在领域带的典型演绎深度。正偏移 = 跨域逻辑同构候选；负偏移 = 该领域内形式化不足。
  • 收敛判据：|offset| ≤ 阈值，最大迭代 12 轮，超限则标记 unresolved 转人工，不得无限迭代。

最值得说的一点：第七节那三个理论风险，全部被翻译成了运行时机制，而不是停在告诫里。

  • 风险一（两尺须独立）→ 变成独立性守卫：schema 声明 main.signal_family ≠ vernier.signal_family 作为结构契约；系统实时计算两尺读数的皮尔逊相关 r。需清醒：本系统两尺当前同源（llm 模式共用同一模型、启发式共用同一本地函数），signal_family 仅为语义标签，故独立性只能靠实证 r 持续监测，而非结构保证。当前种子实测 r ≈ 0.41（健康）。当 |r| ≥ 0.6 且样本充足（≥12）时，守卫真正拦截自动写入（拉闸）并隔离受影响条目的偏移，而非仅上报；运营者通过「重测全部」显式更换 provider 即为复位手段（该命令绕过拦截，否则坍缩后死锁）。
  • 风险二（逻辑非绝对刻度）→ 写入 schema 的 known_limitation 字段：游标读数被明确标注为"本抽取器所操作化的那种逻辑"，而非真理尺。
  • 风险三（领域是谱系的）→ 主尺输出附带置信度：与次优领域越接近，位置越靠向带边界、置信越低。低置信条目在界面上被标为"疑似跨域杂交项"，此时游标比主尺更可信（如"计算神经科学"落在 73.8，正处自然科学与形式科学的交界）。

与独立性守卫正交的，还有信号完整性守卫。独立性守卫管"两尺是否可信地分离"，而信号完整性守卫专管"语义相似信号本身是否可信"：它实时监测 embedding / 语义层的质量，当向量因 provider 变动、模型漂移或抽取失败而劣化时，自动暂停基于语义的关联推荐（软链），只保留硬链与双尺结构，避免把噪声当成"相关"。守卫返回健康度状态（healthy / degraded）供界面与 agent 读取。两道守卫共同构成"数据可用性闸门"——任何一道告警，自动写入与关联推荐都会降级而非硬失败，而非让坏信号静默进入图谱。

九、实测：闭环真的收敛了

数据落 SQLite（核心表与衍生表共二十余张）。核心表：items（原文）、readings（双尺分行存储，各带 provider 与信号族，从结构上强制体现两路独立）、links（候选 / 采纳边）。衍生表：concepts / concept_links（概念衍生层，后端桥接中间件，见第十三节）、feedback_inbox（反馈收件箱，见第十三节）、embeddings / chunks（语义检索与分块）、calib_log（阴阳闭环轨迹）及 FTS 索引簇。九条种子条目的实测结果：

  • 「哲学三段论演绎」：主尺落人文带（典型演绎 20），游标实测 86.2 → 偏移 +66.2。这正是理论预言的明星案例：内容属人文，推理骨架却与形式科学同构。系统据此生成候选边 logic-isomorphism → 形式科学。
  • 触发闭环后，3 轮收敛：主尺自 12.5(人文) 迁移 → 50.0(自然科学) → 68.8 → 78.1(形式科学)，偏移 +66.2 → −3.8，判定对齐。
    这里修正了原型 v2 的一个真实缺陷：旧实现移动主尺位置却从不重新判定所属领域带，典型值恒定，偏移永远不变，循环必然跑满上限而假装"未收敛"。修复的关键正是——主尺一动，领域归属就必须重算。
  • 「量子力学科普」：自然科学带，游标仅 6.0 → 偏移 −54，生成 under-formalized 边。负偏移同样是一等信号：它指认了知识库里"该硬却软"的部分。
  • 「经济学均衡模型」+38.9、「法律判例推理」+38.3、「物理动量守恒」+20.9 —— 三个完全不同领域的条目，被游标测出了同一量级的形式化推理骨架。这就是跨域逻辑同构的自动发现，标签系统与知识图谱都给不出这个结果。

候选边默认状态为 candidate，需人工采纳后才转 accepted 入正式图谱 —— 呼应第六节的分工：卡尺管发现，图谱管确定，闭环管生长。

十、接入真实大模型：独立性靠什么保住

第九节的读数出自本地启发式。现已接入真实大模型（agnes-2.5-flash，OpenAI 兼容端点）， 但这里立刻撞上一个足以让整套理论破产的问题——

致命问题：schema 规定两尺信号族必须不同。可如果两尺都去问同一个大模型， 仅靠 prompt 措辞说"你只管领域"、"你只管逻辑"，那不过是君子协定。同一个模型看着同一段文字， 两个读数必然高度相关，偏移退化为噪声，闭环当场破产。

解法：把独立性从 prompt 层下沉到输入层。系统对原文做一次严格互补的 token 切分， 两尺各自只拿到其中一半，且两半交集为空：

  • 主尺（阳·学科领域）的输入 = 丢弃全部论证功能词，只留实义词。
    「因为人皆会死，所以苏格拉底会死；若甲是乙则丙，综上推论其必然成立，前提充分且必要。」
    → 人会死 苏格拉底会死 甲乙丙 其 且　它看不到任何推理结构。
  • 游标（阴·演绎深度）的输入 = 丢弃全部实义词，替换为 甲/乙/丙 变量符号，只留论证骨架。
    → 因为甲皆乙，所以丙；若丁是戊则己，综上推论庚必然成立，前提充分辛必要。
    同一实义词映射到同一符号，故三段论的指代结构完整保留，但它根本不知道这段属于什么学科。

这不是措辞上的约束，是信息论意义上的隔离：两路模型物理上拿不到对方赖以判断的证据。 界面「输入信息隔离」面板会把任一条目的两路输入直接摊开，可自行核验交集为空。

实测结果（九条种子条目，真实模型）：

  • 独立性守卫 r = 0.286，落在 healthy 区（|r| < 0.6）。
    如实记录：相较本地启发式的 r = −0.021，相关性确有上升——毕竟两路共用同一模型权重， 互补切分能隔断信息、隔不断先验。这说明输入隔离是必要条件而非充分条件；若未来样本量增大后 r 越过 0.6， 正确的做法是把其中一路换成异构模型（如游标改用视觉/结构模型看版式），而不是调 prompt。
  • 理论预言被真实模型一次命中：「哲学三段论演绎」在启发式版需跑 3 轮闭环才从人文迁移到形式科学； 真实主尺直接判定为形式科学 @88.0（置信 0.95）。跨域逻辑同构不再依赖闭环补救，在首次测量就被识别。
  • 误报被消解：「物理动量守恒」在启发式版偏移 +20.9 判为碰撞，真实模型给出 65.0 vs 典型 60， 偏移 +5.0 判定对齐——启发式的词频代理会高估短句的形式化程度，真实模型纠正了这个假阳性。
  • 负偏移信号稳定复现：「量子力学科普」偏移 −55、「进化论观测报告」−55， 两者游标读数均为 5.0（游标看到的确实只是「甲，乙，丙。」这样的纯描述骨架）。
  • 闭环在真实 provider 下仍收敛：「经济学均衡模型」偏移 +27 → 1 轮收敛至 +12。 且校准过程缓存计数未增加——游标以温度 0 + 磁盘缓存实现确定性重算， 既满足"每轮回扣原文"的锚约束，又不重复计费。

仍需诚实指出的局限：领域带只有四条、典型值粗糙，导致「经济学均衡模型」收敛后被归入自然科学带 ——机制正确，但刻度分辨率不足。这是标定问题，不是原理问题，增设子带即可缓解。

十一、下一步

① 游标换异构模型：当前两尺共用一个文本模型，靠输入隔离维持独立；换成视觉/结构模型看论证版式， 可从根上消除共享先验，把 r 压回 0 附近。
② 细化领域带刻度：四带太粗，需引入子带与更可信的 typical_vernier 标定。
③ 成本控制：重型 provider 仅在首次入库或含视觉内容时运行，其余走周期性重校准（已用缓存层兑现一半）。
④ 与灯笼工作台知识库打通：让检索从"按目录找"变成"按任意两尺组合切片"。

值得强调的是：这次接入真实模型，偏移公式、碰撞判定、候选边生成、收敛循环没有改动任何一行—— 改的只是两个 provider 函数。这正是第八节先把 schema 定下来的回报。

十二、归属的再定位：人是定义者，agent 是使用者

前十一节都在谈"这东西怎么度量、怎么闭环"。但还有一个更前置的问题：知识库到底给谁用？

一个朴素的误区是：知识库 = 给人检索的界面。在 AI 时代这站不住。人的角色应当收缩到定义—— 定义知识的构成逻辑（领域带如何划分、主尺/游标怎么读）、定义存储与展示的形式、定义 agent 的授权边界。 而知识的实际使用与关联性处理，应交还给 agent：检索增强、关系图构建、跨域多跳推理， 这些"怎么用、怎么把分散的知识连成一张网"的判断，是 agent 在运行时自主完成的职责，不该由人在界面上点。

沿着这个定位，我们把系统切成两层：

  • 人类层（定义台 / 展示窗）：index.html 只用于定义构成逻辑、配置 provider、校验展示。它不提供面向人的"使用"入口。
  • Agent 层（运行时 / 消费方）：知识库真正的使用方。我们在 kb.py 中把"查找原语"升级为"关系处理引擎"， 新增四个以 agent 为主语的工具——kb_relate（关系图）、kb_context（检索增强包）、 kb_traverse（多跳遍历）、kb_schema（人类定义快照）。它们与 REST / MCP 共用同一实现，行为完全一致。

这带来一个清晰的分工：人类定"坐标系"，agent 在坐标系里"运动"。坐标系错了（领域带划分、阈值）人来纠； 而在坐标系内的检索、关联、推理，agent 说了算。前端界面因此主动降级为"展示窗"——它证明 agent 能拿到什么， 而不是人去操作什么。这样一来，知识库才真正成为可嵌入任意 agent 工作流的基础设施，而非又一个要人盯着的 App。

十三、理论落地的两个引擎：反馈收件箱与概念衍生层

前十二节把系统收敛成"卡尺 + 闭环"的抽象。真正让它能自我生长、且不把噪声直接塞进图谱的，是两个落地的后端引擎——它们把第五节"阳生阴：校验差异 → 推理修订"和第六节"图谱管确定、卡尺管发现"从比喻变成了数据表与异步流程。

13.1 反馈收件箱（feedback inbox）：让闭环的"阳生阴"有处落脚

第三节预言"未对齐 = 待校验信号"，第九节的候选边只是其中一类。系统把所有来自卡尺 / 闭环的差异信号（偏离域典型过远、跨域同构候选、自对抗审查结论）统一收口到独立数据表 feedback_inbox，而非写回知识文章正文——正文因此保持纯净，审查意见与文章本身解耦。

  • 两条呈现通道：前端以右下角 QQ 式弹窗（单条推送、3 分钟节流、仅推高含金量项）呈现待办；以顶栏铃铛徽标 + 侧边"反馈邮箱"列表呈现全部。两者读同一张表，状态（unread / read / applied / dismissed）互通。
  • 硬删除管理：除软状态外，反馈邮箱支持彻底删除（物理删除记录），区别于 dismiss 的"软忽略"——噪声可以真正清掉，而非只是标记。

这样，图 3 的"差异报告即游标偏移＝反馈信号"不再只是图注，而是一条可消费、可清理、可回写的闭环回路。

13.2 概念衍生层（concepts + concept_links）：图谱与卡尺之间的桥

第六节强调"卡尺管发现、图谱管确定"。但图谱若只收作者手打的硬链（[[...]]），发现力为零。系统引入概念衍生层：入库即抽取条目中的概念节点（concepts），并以"共享概念"自动生成软链（concept_links）——它不是图谱节点，而是后端桥接中间件，显式区分"作者意图（硬链）"与"引擎洞察（软链）"。

  • 节点详情页据此推荐"相邻知识"与"相关文档"——这些推荐条目以带边框的小盒子封装隔离，视觉界限清晰，不与原文档正文混排。
  • 这是灯笼比"被动镜像式 wiki"多出来的一层：作者意图 ↔ 引擎洞察的对话，而非把关键词直接塞进图谱造成混乱。

十四、知识生命周期的原点：灵感碎片（原料层）

前十三节把系统讲成了"卡尺 + 闭环 + 双引擎"。但还有一个最前置、也最容易被忽略的问题：库里的知识，到底从哪来？

直觉会答"从收藏的文章、从写过的历史文章来"。这不对。收藏与历史文章是既有来源，是别人或过去的产出，它们不是原点。真正的原点是灵感碎片——你随手记下的、还没成形的念头。它比收藏的文章、比已写过的文章都更重要：新内容是从这里长出来的，它是后续诞生一切的真正核心原料，是出发点。

图 4 · 知识生命周期：灵感碎片是原点（刻意无坐标），聚类萌发只摊开结构，孵化才投影成坐标；收藏 / 历史文章只是既有来源，非原点

这一层刻意【无坐标】：捕获时不做任何双尺度投影，领域归属与演绎深度都推迟到"孵化"环节，由 kb.add_knowledge 完成。这保证"先有原料，后有坐标"——碎片的本质是出发点，强行在捕获时投影会污染原点的纯粹性。

  • 捕获（spark-add）：随手记一条想法，存进 sparks 表，status 恒为 raw。捕获界面不出现领域带 / 游标读数。
  • 聚类萌发（spark-clusters）：离线关键词共现 + 并查集聚类，只呈现"这些碎片似乎在讲同一件事"的主题簇（shared_terms + members）。它是"摊开结构、不下结论"的软洞察——绝不替你判定该合并，孵不孵化由人定。
  • 智能孵化（spark-hatch）：孵化不是"把碎片搬进 items 表"，而是触发全库联动的一次系统事件。它由 kb.hatch_spark 执行六阶段管线，让新原料真正"接入并重塑整张知识网"：
    1. 冗余闸门：孵化前先 kb.query 判命中（阈值默认 4.0）。命中则增量合并既有条目——保留其 id 与双尺定位，仅追加带日期的证据——不新建；未命中才新建。这复用步骤 E upsert-kb 的命中逻辑，从根上消除"同一想法重复建条目"的搬运感。
    2. 投影富化：查碎片所属簇，把 shared_terms 预填 axis_domain 建议，并在正文留"孵化自灵感碎片（簇主题：…）"元痕（不下结论，仅留痕）。
    3. 全库关联发现：新建后以新节点为中心跑 suggest_links，把潜在关联写成 links(confirmed=0) 软边，回报 links_found——新条目立即重织知识图谱，这就是"整体知识库的一点点关联影响"。
    4. 反馈轴自检：坐标偏离所在域典型（collision）/ 使用了库未注册的新域 / 有近似但未达合并阈值的条目 → 各推一条 feedback_inbox（🔔），让库自我更新、用户看到提示。
    5. 簇血缘：同簇未孵化兄弟自动标 incubating（联动），血缘写入 hatch_events；溯源从"碎片→条目"升级为"簇→多条目 + 兄弟联动"。
    6. 事件日志：本次孵化落 hatch_events，供 kb.hatch_stats() 聚合（总孵化数 / 按决策·学科域分布 / 近 7 天趋势 / 累计关联·反馈·血缘数）——库能"反思"自己的生长，Skill 可据以校准轴绩点（哪些透镜最近热）。

出口有两种：碎片已较完整则直接智能孵化（六阶段管线）；碎片只是粗糙出发点则先转步骤 A–E 深度策展（多轴拆解）再孵化。无论哪条路，闭环都从原点启动。前端「灵感碎片」视图（捕获盒 / 列表 / 聚类 / 孵化报告）与 /api/sparks/*、/api/hatch/stats 接口、以及 lantern-method 的步骤 0，都走同一套 kb.* 引擎，行为一致。
